# Cane C++ 运行时

[English](README.md) | **简体中文**

本目录独立实现普通 Godot 4 GDExtension 使用的原生 C++ Core，目标为 Cane Runtime Format 1.0 和 Runtime API 1.3。
Core 生产代码不依赖 C#、TypeScript、Rust、C ABI、编辑器、Bevy 或 Godot。
`cane-godot` 中的 Godot 适配器使用 Core 输出的最终数据包。

## Core 与 Godot 集成

C++17 Core 负责 JSON/CANEB 和 Atlas 加载、动画轨道/队列/混合、全部五类约束、Physics、皮肤与变形、
裁剪、最终数据包、实例资源、可复用 Bounds、查询及事务化播放器状态。
它发布具有独立所有权的结果，不依赖引擎或托管运行环境。

公开接口约定见[加载](docs/LOADING.md)、[播放器控制](docs/PLAYER.md)、[约束](docs/CONSTRAINTS.md)、
[几何](docs/VERTEX_GEOMETRY.md)和[资源](docs/RESOURCES.md)。
[原生 Godot 适配器](cane-godot/README.zh-CN.md)通过 GDScript 提供 Core 控制并投影最终数据包，
其[安装指南](cane-godot/docs/INSTALLATION.md)介绍源码安装和平台要求。

## 数据与所有权

[分阶段加载外部资源](docs/LOADING.md)在构建完整 `RuntimeData` 前提供具有独立所有权的解码请求。
独立图片的尺寸可以留待宿主解码像素后确定；完成阶段验证完整的实际尺寸目录，失败时不改变已有资源。
Godot 加载器对 JSON 和 CANEB 都使用这条 Core 路径。

[实例资源](docs/RESOURCES.md)提供有序的图片/Atlas/附件/皮肤替换、独立构建器和原子验证与求值。
资源事务保留兼容的实时钟、队列、事件游标、宿主覆盖和 Physics 历史，已有帧和其他播放器仍拥有原始数据。

仓库根目录是多语言容器，只有本语言目录是 CMake 工程。JSON for Modern C++ 3.12.0 是内部数据传输依赖，
公开头文件不暴露其类型。随附声明记录上游版本、许可证和源码哈希，详见[依赖来源](third_party/nlohmann/README.md)。

## Atlas 元数据

```cpp
#include <cane/atlas.hpp>

auto atlas = cane::AtlasData::from_json(atlas_json_utf8);
atlas.validate_image_ids(runtime_image_ids);
atlas.validate_decoded_page_sizes(decoded_pages);
const auto& region = atlas.region_for_image("image-body");
const auto& page = atlas.pages()[region.page_index];
```

`AtlasData` 拥有不可变元数据，输入缓冲区释放后仍有效。副本共享该不可变数据；只要所属数据仍被保留，
目录内部引用就有效。加载时验证原生页面名称、可移植路径、限定模式、唯一标识、边界与来源裁边、
四组声明 UV，以及包含边缘扩展纹素的页面分配区域是否重叠。重叠检查使用 O(n log n) 扫描线算法和半开矩形，允许边缘相接。

Atlas 文档本身无法解析 Runtime 图片 ID，因此图片目录验证单独进行。
解码页面验证要求每个页面恰好出现一次，并拒绝与实际解码资源不符的尺寸。纹理 I/O 由宿主负责。
`RuntimeData` 将 Atlas 区域与完整图片目录关联，并在加载时验证资源所属关系和路径。

Atlas UV 按声明的来源角点顺序复制。Godot 适配器直接上传 Core 的最终 UV、几何和颜色，不重新计算。
原生元数据加载与引擎纹理获取、播放保持分离。

## 具有独立所有权的 Runtime 数据

[目录与纹理查询](docs/CATALOGS.md)提供文档版本、生成器标识、完整原生声明和独立的解码资源描述符。
它们包含当前未使用的 Atlas 页面，保留精确整数和可选字段，读取当前有效数据时不进行动画求值。

```cpp
#include <cane/runtime_data.hpp>

cane::RuntimeLoadOptions options;
options.atlas_json.emplace("atlas-hero", atlas_json_utf8);
auto data = cane::RuntimeData::from_json(runtime_json_utf8, options);
// Alternatively: cane::RuntimeData::from_caneb(caneb_bytes, options).
data.validate_decoded_texture_sizes(decoded_texture_facts);
const auto& bones = data.bones();
const auto& animations = data.catalog(cane::RuntimeCatalogKind::animation);
```

数据副本共享不可变存储，加载后可以释放输入缓冲区和选项。资源目录保留声明顺序，链接几何所有者与变形所有者分别解析。
可选 CANEB 段的警告与原生文档数据分开保留。只应提供已声明的 Atlas 标识。
可选解码事实必须让每张独立图片和每个 Atlas 页面恰好出现一次，包括未使用的页面。
未声明尺寸的独立图片在加载时需要这些事实，不会因此改写来源 JSON 字段。

动画编译仅解析一次 ID，即使轴属性来自不同记录，也会合并成对和单轴数据流，并保存不含 JSON 引用的
类型化标量、向量、离散、事件和顺序通道。骨骼轴数据流选择 `x/y` 属性曲线，Region 缩放选择 `scale_x/scale_y`。
事件保留所有同时间声明及精确的有符号 64 位载荷。Physics 重置仍以关键帧跨越为触发条件，
之后同时间的 false 关键帧不能抹掉 true 触发。向量采样接受调用方拥有的暂存区。
来源文档保留用于目录、持久化和覆盖操作。已知必需功能默认可加载，未知功能始终被拒绝。

## 内部求值流程

加载时还会将 Slot 颜色、全部附件几何、皮肤映射与成员关系，以及五类约束定义编译为独立的类型化数据。
逐帧姿势求值不读取 JSON。动画层组合骨骼/Region 变换、舍入后的颜色字节、alpha、稀疏约束参数、
两种变形空间、附件/皮肤选择、完整或文件夹绘制顺序，以及全部七种序列模式。
第一个声明的 Skin 是默认皮肤，与名称无关；隐式回退改变附件解析，但不激活回退皮肤所属的骨骼或约束。

通用顶点求值处理 Mesh、Path、Bounding Box 和 Clipping 来源的非加权位置，以及显式和绑定逆变换坐标混合的加权数据。
零权重影响保留自己的变形偏移位置，正权重按实际总和归一化。链接网格分别使用几何与变形所有者，
同时保留显示附件的 Slot、图片和颜色。Region 来源四边形使用当前序列图片的完整尺寸。
Point 姿势保留完整的骨骼/附件仿射变换。

`Pose` 是内部可变工作区，不是公开帧或不完整的公开播放器。
求解器更新几何计算所用的同一组矩阵；引擎仅使用裁剪、Atlas 投影和发布之后的最终数据包。

## 原生约束求解

IK 包含单骨骼和双骨骼解析路径、CCD 回退、两种弯曲方向、压缩/拉伸、三种 scale-Y 策略、柔化、
精确零激活和残差诊断。可复用工作区避免重复 CCD 求值时分配链和旋转暂存内存。
Transform 支持局部/世界与绝对/相对模式、不限制范围的属性混合、有序属性路由、默认钳制、
精确的规范 Match 查询和指定轴残差。

世界变换写入保留完整矩阵并立即刷新后代。已应用局部变换的重建覆盖五种继承模式；
遇到奇异逆矩阵或退化轴而无法重建时，世界结果仍为最终依据，最近有效的局部姿势保持可用。
加载会拒绝位于受驱动子树内的 Transform 目标，以及重复的映射来源或目标。

Path 使用已变形的世界控制点、四次细分的粗略长度表与独立的十次细分正向查找、
创作时的初始长度参数化及其 24 次细分回退，以及单独的 24 次细分反向投影。
开放路径的外推使用原始端点控制柄，闭合环绕和退化段遵守精确比较规则。
所有受驱动骨骼读取同一份未变化的世界快照，暂存结果后按骨架顺序提交。
未受驱动的后代只刷新一次，不相关的前序约束结果保持不变。

Slider 通过同一类型化动画层求值器采样目标片段。六种来源属性区分已应用局部值和仅移除一次宿主根变换的世界值。
手动时间、来源钳制、负值环绕、零或极短时长、外推混合，以及解析之后的固定帧/阶梯采样保持独立分支。
目标采样改变之后参与求解的约束参数，不进入第二次求解，也不推进动画时钟或发出目标事件。

Physics 实现固定步长的平移、旋转、错切和缩放积分，支持全部 scale-Y 策略、环境向量、
有符号宿主缩放及合计一百万子步限制。原始动画时间控制重置关键帧跨越，量化采样时间控制积分经过时间。
历史由实例独立拥有，保留完整仿射宿主运动，并支持指定的 reset/teleport/preserve-inertia/clear-inertia 策略。
历史传递在提交前验证所有选中的历史。统一调度器按声明顺序，在同一姿势与预算上各调用五类求解器一次。
公开播放器拥有该事务，并在所有约束和重放步骤之间共享总预算。

## 最终渲染数据包

内部 `geometry::PacketBuilder` 读取一个已求解的 `Pose`，返回公开不可变 `RenderPacket`，不采样或求解动画。
数据包副本保留独立拥有的不可变存储；之后成功或失败的构建都不能改变已有数据包。
公开播放器拥有构建器，将姿势、时钟、宿主状态、求解器历史、事件和发布一起作为事务处理。

裁剪遵循最终 Slot 顺序，后一个裁剪替换前一个而不嵌套，结束 Slot 也包含在裁剪范围内。
确定性的凸包/耳切法、凸多边形相交和凹多边形反向减法会在交点之间传递来源 UV。
Region 以完整来源四边形进入裁剪；之后在来源 UV 空间执行 Atlas 裁边，保留范围内拓扑，
并使用 binary64 中间值映射声明的旋转页面角点。空结果不产生绘制，后续绘制索引保持连续。

每个数据包声明最终世界坐标 XY、页面 UV、有序索引、限定类型的纹理标识、最终颜色和混合方式，
以及在归一化为逆时针绕序之前记录的每三角形创作朝向。裁剪后的 Region 始终使用 `mesh_triangles`。
奇异或不可投影的来源矩阵使用单位矩阵作为诊断结果，有限的世界几何仍可显示。
三角形面积溢出会在发布前失败。每个附件最多输出 65,536 个顶点，暂存缓冲区在多次求值间保留。

## 事件遍历与独立发布

内部事件收集器使用编译后的事件关键帧和调用方提供的原始时钟区间。
它保留前向/反向半开区间归属、同时间声明顺序、范围起点的一次初始化、精确零与极小正时长、
非循环反向重新进入，以及每次跨越的循环完成事件。淡出条目的创作事件在每次跨越时使用严格阈值，
完成事件不会被此阈值抑制。区间内时间偏移在排序过程中保持 binary64，随后按轨道索引、
淡出至淡入的条目顺序、边界退出阶段和条目内部顺序排序。

播放状态的所有者先通过计数接收器执行完整操作，再用确切计数通过收集接收器重放已验证的事务。
生命周期事件和创作事件共享一百万总数限制，重放可传入自己的剩余预算。
不可能完成的循环计数会在遍历前被拒绝。收集器借用一个条目，返回建议的游标值而不修改条目。
公开 `EventBatch` 拥有所有标识符和载荷，包括精确的有符号 64 位整数；来源数据及编译关键帧释放后仍有效。

循环计数在遍历前检查实际 binary32 边界归属，避免商的舍入从剩余预算中扣除并不存在的完成事件。

## 原生播放状态

`animation::Playback` 拥有独立轨道时钟、队列和有序动画对的混合配置。
每条轨道保存从最旧到最新的扁平混合链，避免递归遍历与销毁。
时钟保留有符号循环时间、非循环尾部、冻结/反向速率、动画子范围、轨道结束和不受播放速率缩放的混合进度。
大步长更新以 binary64 在队列、结束和混合边界拆分；队列推进与轨道结束同时发生时，队列推进优先并保留超出的时间。
移除的混合条目在各自完成边界停止推进，按从新到旧的顺序退出。
队列条目进入播放后仍保留标识，使公开播放器可在配置基线中访问同一条目。

混合器先应用最早的淡出层，再应用淡入层；低轨道先于高轨道。
每条目 alpha、类型化结构属性所有权、低轨道所有权、hold-previous、空混合链渐隐、叠加组合和
淡出附件/顺序阈值分别处理。属性和混合链暂存存储会跨求值复用。

公开播放器先在独立候选状态上计数事件，再收集精确数量的事件并计算完整候选状态，
最后通过一次不会抛出异常的状态交换提交。求值失败保留此前时钟、基线、宿主状态、Physics 历史、事件和不可变 Frame。

## 公开播放器

[播放器 API 与所有权](docs/PLAYER.md)介绍加载、播放、固定步长重放、事件消费、当前姿势查询和宿主覆盖。
`update` 推进时钟与待处理事件而不发布帧；`apply` 发布当前姿势；`advance` 以事务方式组合两者。
绝对时间重放从配置基线及全新 Physics 历史开始，返回重放事件而不修改增量待处理事件。
固定步长端点保留相邻 binary32 关键帧时间。重置清除播放与宿主配置，但保留已安装资源；
配置克隆保留宿主覆盖和混合设置，不复制播放时钟或历史。

## 公开约束

类型化可选覆盖包含 IK、Transform、Path、Physics 和 Slider。播放器提供采样参数记录、求解器诊断、
Path 正向/反向位置查询和规范 Transform Match，详见[约束控制与查询](docs/CONSTRAINTS.md)。
宿主可编辑设置是实例独立的采样值，定义仅保留不可变标识、成员关系和路由数据。
已安装补丁中的显式 IK 点优先于创作时指定的目标骨骼，替换或清除补丁会恢复相应的采样目标行为。

[已发布 Slot 查询](docs/SLOT_QUERIES.md)提供完整采样顺序和所属骨骼姿势，不进行求值。

[Point 与骨骼激活状态查询](docs/POINT_QUERIES.md)提供完整仿射及已发布的选中/激活状态，不增加规范化传输字段。
